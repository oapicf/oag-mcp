# OAG MCP

An open-source CLI that turns OpenAPI specifications and OpenAPI Generator SDKs into code-mode MCP servers, exposing searchable SDK capabilities and sandboxed SDK execution through two tools: `search` and `execute`.

## Why oag-mcp

Most OpenAPI-to-MCP bridges expose one MCP tool per endpoint, or a generic
HTTP request tool. oag-mcp takes a different approach — **SDK-backed code
mode**:

- **OpenAPI supplies the contract and documentation**: descriptions, tags,
  parameters, schemas, examples and security requirements.
- **The generated typescript-fetch SDK supplies the callable interface**:
  the exact classes, methods, signatures and model types.
- **`search`** discovers relevant SDK methods with their signatures,
  referenced types, auth requirements and a ready-to-run example.
- **`execute`** runs agent-written TypeScript that composes real SDK calls —
  loops, filtering, aggregation, `Promise.all` — inside an isolated Deno
  sandbox, and returns only the compact result.
- **The same SDK stays an ordinary package** that applications and CLIs use
  directly; oag-mcp never modifies it.
- **MCP sees two tools**, not one per endpoint, so large APIs don't flood the
  agent's context.

```text
                    oag-mcp serve (one process)
 openapi.yaml ─┐   ┌──────────────── start-up, once ────────────────┐
               ├──▶│ 1 inputs  2 compatibility  3 bundle + .d.ts     │
 SDK dir/.tgz ─┘   │ 4 method index  5 bridge + Deno executor        │
  (read-only)      │ 6 register search/execute  7 start transport    │
                   └───────────────────────┬─────────────────────────┘
                                           ▼  (stdio or Streamable HTTP)
                    search ─▶ in-memory index
                    execute ─▶ type check ─▶ Deno sandbox (real SDK) ──┐
                               host broker: authz, network, credentials ◀┘ ─▶ your API
```

## Installation

```bash
npm install -g oag-mcp
```

Requirements:

| What | Needed for | Notes |
| --- | --- | --- |
| Node.js 22+ | everything | |
| Deno 2.x | `execute` (and start-up verification of the SDK bundle) | Installed automatically through the `deno` npm dependency; or set `OAG_MCP_DENO_PATH` / put `deno` on `PATH`. |
| An existing typescript-fetch SDK | everything | Generated by you with [OpenAPI Generator](https://openapi-generator.tech) 7.25.0 or 7.26.0. oag-mcp does not generate SDKs, and needs no Java, Docker or OpenAPI Generator. |

No account, licence, cloud service or telemetry is involved. Network access is
only used to install oag-mcp itself and for calls to your own API.

## Quick start

### 1. Have a typescript-fetch SDK

Any SDK generated with `-g typescript-fetch` works, as a package directory or
an `npm pack` archive, for example:

```bash
openapi-generator-cli generate -g typescript-fetch -i openapi.yaml -o ./generated-sdk
```

### 2. Serve it

```bash
oag-mcp serve --spec ./openapi.yaml --sdk ./generated-sdk --transport stdio
oag-mcp serve --spec ./openapi.yaml --sdk ./generated-sdk \
  --transport streamable-http --port 3000
oag-mcp serve --spec ./openapi.yaml --sdk ./my-sdk-1.0.0.tgz --transport stdio
```

That is the whole workflow: there is no build step and no generated server
directory. At start-up oag-mcp checks the SDK, prepares it for the sandbox
and indexes its methods (typically 1–3 seconds), then accepts MCP requests.
If anything cannot be prepared it exits with an actionable error instead of
starting a partially working server.

Example MCP client entry (stdio):

```json
{
  "mcpServers": {
    "petstore": {
      "command": "oag-mcp",
      "args": [
        "serve", "--spec", "/path/to/openapi.yaml", "--sdk", "/path/to/generated-sdk",
        "--transport", "stdio", "--config", "/path/to/oag-mcp.config.yaml"
      ],
      "env": { "PETSTORE_API_KEY": "…" }
    }
  }
}
```

### 3. Configure upstream credentials and access (optional)

```yaml
# oag-mcp.config.yaml — contains references to secrets, never secret values
upstream:
  baseUrl: https://api.example.com/v1   # default: the spec's first absolute server URL
upstreamAuth:
  schemes:
    apiKeyHeader:            # security scheme name from the OpenAPI document
      apiKey: { env: PETSTORE_API_KEY }
```

```bash
oag-mcp serve --spec ./openapi.yaml --sdk ./generated-sdk --config ./oag-mcp.config.yaml
```

Secrets are resolved at runtime from environment variables or a `0600`
secrets file; they are never accepted as CLI arguments and never written to
the index, the prepared bundle, logs or anything agent code can read. See
[authentication](docs/authentication.md) for MCP access control
(`mcpAuth`), upstream credentials (`upstreamAuth`) and per-operation
`authorization`.

### Start-up preparation, restarts and temporary files

- The SDK and spec are read **once per process**. The index, bindings and
  sandbox bundle stay fixed until the server exits; **restart oag-mcp after
  changing the spec or SDK** (there is no watch mode).
- The supplied SDK is never written to. oag-mcp does not install packages,
  run package scripts or SDK build scripts. If the SDK declares runtime
  dependencies, install them yourself (`npm install --omit=dev
  --ignore-scripts` in the SDK directory) — a missing one stops start-up
  with `SDK_DEPENDENCIES_MISSING` and these instructions.
- Preparation output (declarations, the sandbox bundle, an extracted
  archive) lives in a private `oag-mcp-ws-*` directory under the OS
  temporary directory (`TMPDIR`). It is removed on shutdown and on start-up
  failure, and leftovers of killed processes are removed by the next start.
  There is no persistent cache and nothing to manage.

See [SDK compatibility](docs/sdk-compatibility.md) for supported generator
versions, options and package layouts.

### Migrating from `oag-mcp build`

Earlier pre-releases used two steps, `oag-mcp build … --out ./server` and
`oag-mcp serve ./server`. Both the `build` command and artifact
directories are gone:

| Before | Now |
| --- | --- |
| `oag-mcp build --spec S --sdk D --out ./server` then `oag-mcp serve ./server …` | `oag-mcp serve --spec S --sdk D …` |
| `build --sdk-layout`, `--sdk-oag-version`, `--allow-untested-oag-version` | the same options on `serve` |
| `build --generate-sdk`, `--oag-version`, `--oag-backend`, `--oag-jar`, `--oag-options` | generate the SDK yourself with OpenAPI Generator, then pass it to `--sdk` |
| automatic `npm install` of SDK dependencies (`--no-install` to disable) | never installs; install dependencies in the SDK yourself |
| `--skip-verify`, `--force`, `--out` | removed |

Runtime configuration files (`--config`) and every `serve` transport, auth
and logging option are unchanged. Delete old artifact directories; update MCP
client entries to pass `--spec` and `--sdk`.

## The two tools

### `search`

```jsonc
// browse when the vocabulary is unknown
{ }
// ranked full-text search
{ "query": "vet visits of a pet" }
// full detail for one method
{ "id": "PetsApi.listPetVisits" }
```

A detail result (abridged):

```json
{
  "method": {
    "id": "PetsApi.listPetVisits",
    "sdkPath": "sdk.PetsApi.listPetVisits",
    "operationId": "list-pet-visits",
    "httpMethod": "GET",
    "path": "/pets/{petId}/visits",
    "signature": "listPetVisits(requestParameters: ListPetVisitsRequest, initOverrides?: RequestInit | runtime.InitOverrideFunction): Promise<Array<Visit>>",
    "requiredArguments": ["petId"],
    "inputType": "interface ListPetVisitsRequest {\n  petId: number; // Identifier of the pet\n  since?: Date; // Only visits on or after this date\n}",
    "referencedTypes": ["interface Visit {\n  id: number;\n  date: Date;\n  reason: string;\n  costCents?: number;\n}"],
    "auth": "apiKeyHeader(apiKey-header) OR bearerAuth(http-bearer)",
    "example": "const result = await sdk.PetsApi.listPetVisits({ petId: 1 });\nreturn result;"
  }
}
```

Note that the binding is the SDK's own method name (`listPetVisits`), not the
operationId (`list-pet-visits`): oag-mcp maps them from the generated code
rather than assuming they are equal.

### `execute`

The agent writes the body of an async function; `sdk` is provided:

```ts
const pets = await sdk.PetsApi.listPets({});
const unvaccinated = pets.filter((p) => !p.vaccinated);
const visits = await Promise.all(
  unvaccinated.map((p) => sdk.PetsApi.listPetVisits({ petId: p.id })),
);
return unvaccinated.map((p, i) => ({
  pet: p.name,
  spentCents: visits[i].reduce((s, v) => s + (v.costCents ?? 0), 0),
}));
```

Result:

```json
{
  "ok": true,
  "result": [
    { "pet": "Biscuit", "spentCents": 8100 },
    { "pet": "Nori", "spentCents": 8400 },
    { "pet": "Tofu", "spentCents": 8700 },
    { "pet": "Pip", "spentCents": 9000 }
  ],
  "logs": [],
  "stats": { "durationMs": 131, "sdkCalls": 5 }
}
```

TypeScript is type-checked against the SDK declarations before it runs.
Failures are structured: `syntax_error`, `type_error` (with line/column
diagnostics), `api_error` (HTTP status and body), `sdk_error`,
`upstream_auth_error`, `permission_denied`, `timeout`, `output_limit`,
`resource_limit`, `unsupported_result`.
